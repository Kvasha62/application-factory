# Learning — Business System (первый реализационный срез)

**Класс:** A — Business System
**Уровень:** Level 0 — Modular Monolith
**Версия компонента:** 0.1.0
**Версия API:** v1 (`/api/v1/learning`)
**Владелец данных:** `learning` (логическая схема `learning`)
**Архитектурная основа:** `docs/ARCHITECTURE.md` v1.2.0 §3, §5.3, §5.4, §6.1,
§6.2, §26, §27, LAW-03, LAW-04, LAW-05, LAW-16, LAW-16a

Learning — самостоятельная бизнес-система обучения: курсы, модули, уроки,
задания, записи на курс и решения студентов. Компонент владеет своими
данными и является финальной границей контроля над ними.

Срез реализует ровно одиннадцать операций, определённых контрактом
(разделы 8–14): семь явных бизнес-команд и четыре чтения. Универсального
CRUD нет: `PUT`, `PATCH` и `DELETE` для ресурсов среза не существуют ни в
реализации, ни в контракте. Оценка работ (grading), события и CDC не
заявляются реализованными.

## Цепочка, которая доказывается

```text
Identity (IS-001)
      ↓  проверенная идентичность; эффективный тенант — только из IS-001
Authorization (IS-003)
      ↓  ALLOW — ещё не доступ к данным
Data Ownership (этот компонент)
   ├─ сущность существует в этом хранилище?            иначе 404
   ├─ сущность принадлежит эффективному тенанту?       иначе 403 TENANT_MISMATCH
   ├─ решение власти получено и авторитетно?           иначе 403/503 (закрыто)
   ├─ предусловия команды выполнены?                   иначе 409
   └─ бизнес-эффект — только здесь, внутри IS-005
```

Роли Teacher и Student — не механизм компонента, а опубликованные наборы
грантов операций внутри IS-003:

| Роль | Операции IS-003 |
|---|---|
| Teacher | `learning.course.write`, `learning.course.read`, `learning.assignment.read`, `learning.submission.read` |
| Student | `learning.course.read`, `learning.assignment.read`, `learning.enrollment.write`, `learning.enrollment.read`, `learning.submission.write`, `learning.submission.read` |

## Идемпотентность (IS-005)

Каждая изменяющая состояние операция требует заголовка `Idempotency-Key` и
доставляется через опубликованный guard IS-005. Ключ связывается с
идентичностью, эффективным тенантом, операцией, целью и отпечатком запроса
(canonical JSON, SHA-256):

* точный повтор возвращает тот же логический результат и не создаёт второго
  бизнес-эффекта;
* тот же ключ с другой полезной нагрузкой, идентичностью, тенантом,
  операцией или целью — отказ `IDEMPOTENCY_CONFLICT` (409);
* отказ авторизации или зависимости не создаёт записи идемпотентности:
  эффект исполняется внутри guard;
* пути в обход идемпотентности нет: ключ — обязательный аргумент каждой
  команды движка и обязательный заголовок контракта.

Публикация курса идемпотентна особенным образом: машина состояний принимает
только `DRAFT → PUBLISHED`, но точный повтор команды с тем же ключом
возвращает уже опубликованное представление, не задевая машину состояний.

## Жизненный цикл

```text
Course:     DRAFT → PUBLISHED        (ARCHIVED объявлен, но недостижим в этом срезе)
Content:    DRAFT → PUBLISHED        (следствие публикации курса, каскад)
Enrollment: ACTIVE
Submission: SUBMITTED
```

Структурные мутации (модули, уроки, задания) принимаются, только пока курс
в `DRAFT`; после публикации — `INVALID_STATE_TRANSITION` (409). Публикация
курса публикует всё его содержимое той же командой.

## Инварианты среза

| № | Инвариант |
|---|---|
| L-001 | Клиент не выбирает эффективный тенант — он выведен из проверенной идентичности |
| L-002 | Клиент не выдаёт себя за другую идентичность — `created_by` и `student_identity_id` выводит сервер |
| L-003 | Клиент не назначает владение и не задаёт состояние жизненного цикла |
| L-004 | Доступ к сущности чужого тенанта запрещён (`TENANT_MISMATCH`) |
| L-005 | Авторизация оценивается до бизнес-эффекта |
| L-006 | Владение данными контролируется на границе Learning |
| L-007 | Обязательные команды не проходят мимо идемпотентности |
| L-008 | Точный повтор не создаёт второго бизнес-эффекта |
| L-009 | Недопустимый переход не мутирует ресурс |
| L-010 | Отказ зависимости не даёт успешного эффекта (fail closed) |
| L-011 | Нет универсального CRUD API |
| L-012 | Нет API оценки работ |
| L-013 | API событий/CDC не заявляется реализованным |
| L-014 | Нет второго механизма идентичности, тенант-контекста, авторизации или идемпотентности |

## Коды отказов

Закрытый набор, каждый код — ровно один HTTP-статус; отказ — это конверт
`{"error": {"code", "message", "details"}, "request_id", "correlation_id"}`
со статическим безопасным сообщением:

| Код | HTTP |
|---|---|
| `IDEMPOTENCY_KEY_REQUIRED` | 400 |
| `AUTHENTICATION_REQUIRED` | 401 |
| `AUTHORIZATION_DENIED`, `TENANT_MISMATCH`, `RESOURCE_OWNER_MISMATCH` | 403 |
| `RESOURCE_NOT_FOUND` | 404 |
| `INVALID_STATE_TRANSITION`, `COURSE_NOT_PUBLISHED`, `ASSIGNMENT_NOT_PUBLISHED`, `ENROLLMENT_REQUIRED`, `DUPLICATE_ENROLLMENT`, `IDEMPOTENCY_CONFLICT` | 409 |
| `VALIDATION_ERROR` | 422 |
| `DEPENDENCY_UNAVAILABLE` | 503 |

## Публичная поверхность

* HTTP-контракт: `components/learning/contract/openapi.yaml`;
* паспорт компонента: `components/learning/contract/component_contract.json`;
* потребительский клиент Level 0: `learning_service.reader.LearningClient`
  (только значения; внутренние модули компонента не являются контрактом).

Зависимости читаются только через опубликованные контракты и адаптируются
на границе композиции: `IdentityContextPort` (IS-001),
`AuthorizationPort` (IS-003), `IdempotencyGuard` (IS-005). Ни один модуль
компонента не импортирует `identity_service`, `authorization_service` или
`tenant_authority`.

## Аудит

Каждая операция и каждый отказ записываются в собственный append-only
журнал компонента с `request_id`, `correlation_id`, идентичностью, тенантом
и целью; события `idempotency_replay` и `idempotency_conflict` пишутся
audit-sink'ом IS-005. Журнал — собственные данные компонента и не читается
через опубликованную поверхность.
